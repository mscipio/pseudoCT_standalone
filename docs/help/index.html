Overview

The Martinos pseudoCT package generates a subject-specific attenuation map from a T1-weighted MPRAGE image using the atlas-based method described by Izquierdo-Garcia et al.

It is intended for PET/MR attenuation-correction workflows at the Athinoula A. Martinos Center for Biomedical Imaging. MPRAGE input can be supplied either as the original DICOM series or as a preprocessed NIfTI image (.nii or .nii.gz).

Routine use

For normal subject processing, use the LOCAL - Current (local-current) profile.

Reference

D. Izquierdo-Garcia, A.E. Hansen, S. Förster, D. Benoit, S. Schachoff, S. Fürst, K.T. Chen, D.B. Chonde, and C. Catana. An SPM8-based Approach for Attenuation Correction Combining Segmentation and Non-rigid Template Formation: Application to Simultaneous PET/MR Brain Imaging. Journal of Nuclear Medicine. 2014;55(11):1825–1830.

Software location and versions

PseudoCT is deployed at:

/usr/pubsw/packages/mrpet/standalone_apps/PseudoCT/

Which version should I use?

For a new subject or a new study, users should normally use pseudoCT_standalone-latest. v3.0.2 is the current documented source; v2.8.4 remains the last published archive. v3.0.0 was withdrawn for an MLSC validation issue, and v3.0.1 was withdrawn because its source wrapper broke the established installation layout. v3.0.2 resolves both; its compiled scientific executable is unchanged. No production deployment is claimed.

Long-running studies: pin a numbered release

If processing for a study will take place over an extended period, select a specific numbered release and use the same version for the entire study. This maintains software-version consistency across the dataset.

New versions will be deployed regularly to add functionality or fix minor issues. If a problem is discovered that makes continued use of an older version inadvisable, that change will be explicitly communicated and motivated.

Quick start

  1. Add pseudoCT to the MATLAB path. From a checkout, add the repository root; from an installed version, add its installation root: 
    addpath('/usr/pubsw/packages/mrpet/standalone_apps/PseudoCT/pseudoCT_standalone-latest')
% installed version layout:
% addpath('/usr/pubsw/packages/mrpet/standalone_apps/PseudoCT/pseudoCT_standalone-3.0.2')
  2. Run pseudoCT. 
    run_pseudo_CT
  3. Select LOCAL - Current for routine processing.
  4. Select the first DICOM of the MPRAGE series, or select the single preprocessed NIfTI file.
  5. Confirm that the UMAP has been found automatically.
  6. Leave the automatic MPRAGE correction options enabled unless you have a specific reason not to.
  7. Click OK and keep MATLAB open until the run finishes.
  8. Inspect both the TIFF fusion image and the final DICOM pseudoCT before using it for attenuation correction.

It is recommended to run pseudoCT from a working directory close to the data rather than changing into the software installation directory.

To pin processing to a numbered release, use that version explicitly (checkout root or installed version root): 

addpath('/usr/pubsw/packages/mrpet/standalone_apps/PseudoCT/pseudoCT_standalone-<version>')
% installed version layout:
% addpath('/usr/pubsw/packages/mrpet/standalone_apps/PseudoCT/pseudoCT_standalone-3.0.2')

Execution profiles

PseudoCT uses profile-based execution. Implementation (current source MATLAB vs legacy-v2 compiled Aether backend) and execution (local workstation vs mlsc cluster vs launchpad remote) are independent properties. Current and Legacy follow different numerical paths; no universal equivalence is claimed. Always inspect the QC image.

Local workstation MLSC cluster
Current source MATLAB local-current (available now) mlsc-current (selectable now; bundled backend included)
Legacy v2.0 compiled (Aether) local-legacy (available now) mlsc-legacy (available now)

Eight profiles exist: five Recommended (local-current, mlsc-current, local-legacy, mlsc-legacy, launchpad-legacy) and three Specialized (local-mprage-only, mlsc-mprage-only, devel). The selector shows exactly the five Recommended rows in fixed order, with WHERE and WHICH visible in each label; the Specialized section starts collapsed and expands with the [+] control. Scripts use the stable canonical keys above, never display labels. The bare key mlsc is only a deprecated alias for mlsc-legacy and creates no selector row. The deprecated keys (launchpad, launchpad-mprage-only, local-near-parity-r2010b) remain excluded from discovery and are not supported.

Standard profiles require the UMAP reference and produce both NIfTI and DICOM output. MPRAGE-only profiles do not require a UMAP and produce NIfTI output only.

LOCAL - Current

Recommended

Runs the full MPRAGE + UMAP workflow locally on the workstation using the current MATLAB source (local-current). This is the recommended profile for routine processing.

On an average workstation, expect approximately 30 minutes per subject.

MLSC - Current

Recommended

Runs the full MPRAGE + UMAP workflow on the MLSC cluster from the current source (mlsc-current). It requires the UMAP reference and produces NIfTI and DICOM output. The bundled backend is included in the installation; use requires a valid cluster account and provisioned paths.

LOCAL - Legacy v2.0 (Aether)

Recommended

Runs the full MPRAGE + UMAP workflow locally on the workstation using the legacy v2.0 compiled backend (local-legacy) with direct-local execution. There is no login dialog and no cluster submission on this path. Recommended where the legacy backend is required.

MLSC - Legacy v2.0 (Aether)

Recommended

Runs the standard MPRAGE + UMAP workflow on the MLSC cluster using the legacy v2.0 compiled backend (mlsc-legacy). It requires the UMAP reference and produces both NIfTI and DICOM output.

Expected processing time is approximately 1 hour per subject, excluding queue wait. Use requires a valid cluster account and provisioned paths.

LAUNCHPAD - Legacy v2.0 (Aether)

Recommended

Runs the full MPRAGE + UMAP workflow on the legacy remote path (launchpad-legacy). Restored as a selectable Recommended profile; this is an availability restoration only with unchanged submission and retrieval behavior. No new correctness claim is made beyond the dataset-specific states recorded in the technical notes.

Specialized / Custom profiles

Three profiles live under the Specialized / Custom disclosure, which starts collapsed on every open and expands with the [+] control: local-mprage-only (Local MPRAGE Only; MPRAGE without UMAP, NIfTI only, local), mlsc-mprage-only (MLSC MPRAGE Only; MPRAGE without UMAP, NIfTI only, on MLSC), and devel (Development Current MATLAB; inspection and development only). They are not intended for routine use.

The deprecated keys (launchpad, launchpad-mprage-only, local-near-parity-r2010b) are never shown in the selector and are not supported.

If you do not already know why you need a specialized profile, do not select one.

MLSC remote workflow

MLSC runs pseudoCT on the cluster for subjects that cannot be processed locally. The same MPRAGE and UMAP inputs and the same final NIFTI/DICOM layout are used; cluster execution and local finalization happen behind the dialogs described below.

What is already validated

The bundled MLSC CURRENT backend already passed controlled validation on MLSC (job 10492486, strict Gate-A PASS, byte-identical to the local-current reference). v3.0.1 added no new scientific or submission run. Use requires an installed bundled backend, a valid cluster account, and the provisioned runtime and resources. No production deployment is claimed by this release.

Login dialog

When a remote profile is selected, MATLAB shows a login dialog asking for the cluster username and password. Credentials are entered at runtime, held only for the connection, and never saved in profiles, scripts, logs, or outputs. Cancelling the login dialog stops before any cluster work is submitted. A rejected login fails without any submission attempt.

Account dialog

After a successful login, available cluster accounts are discovered at runtime. If no account is available, processing stops before submission. If one account is available, it is selected automatically. If several accounts are available, a single-selection dialog is shown; cancelling that dialog submits nothing. The selected account is used only for that run and is not saved.

Progress, completion, and failure

After submission, MATLAB monitors the cluster job and then performs local finalization (including DICOM output for standard profiles). Keep MATLAB open until the run finishes. Closing MATLAB can leave remote work unfinalized even when the cluster job has continued.

A run completes only when the required attenuation map is present and non-empty and local finalization succeeds. Anything else — a failed connection, no account, a cancelled dialog, a failed or cancelled cluster job, a missing or empty attenuation map, or a finalization problem — stops before promotion and leaves the run log and temporary files for diagnosis. Rerunning restarts from the beginning.

Expected processing time is approximately 1 hour per subject, excluding queue wait.

Logs

Each subject receives a detailed run log under MR_PET plus the usual pseudo_CT_profile_summary.txt. Keep both with the QC image when asking for support. They record the selected profile, stages, and final status without credentials.

See the detailed MLSC pipeline documentation for the full technical contract, readiness checks, and output handling.

Preparing the input data

The standard PET/MR workflow requires a T1-weighted MPRAGE and a corresponding UMAP. PseudoCT supports either the original MPRAGE DICOM data or a preprocessed MPRAGE NIfTI. MPRAGE-only profiles are the exception: they do not require a UMAP and produce NIfTI output only.

DICOM MPRAGE

The minimum required folder structure is:

<subject>/
└── MR/
    ├── MPRAGE/
    └── UMAP/

When selecting the MPRAGE, choose the first DICOM file of the MPRAGE series. The MR_PET folder does not need to exist before processing; pseudoCT creates it.

Preprocessed NIfTI MPRAGE

If preprocessing is needed, place the resulting .nii or .nii.gz image in <subject>/MR_PET/. The original MR/MPRAGE and MR/UMAP folders may remain in place. 

<subject>/
├── MR/
│   ├── MPRAGE/
│   └── UMAP/
└── MR_PET/
    └── preprocessed_mprage.nii.gz
Why preprocess the MPRAGE?

In some subjects, noise in the image background can interfere with segmentation and can ultimately produce spurious tissue-like attenuation values outside the head. Background cleanup may be useful in those cases. A dedicated preprocessing tool is planned for release.

Single-subject workflow

After selecting LOCAL - Current, the Load Images dialog is shown.

1. Load the MPRAGE

Click Load MPRAGE. For DICOM input, select the first file in the MPRAGE series. For NIfTI input, select the single .nii or .nii.gz file.

2. Confirm the UMAP (standard profiles)

When the expected directory structure is present, pseudoCT automatically searches the sibling MR/UMAP folder and populates the UMAP field. In normal use, you should not need to click Load UMAP manually. MPRAGE-only profiles skip this step by policy because they do not use a UMAP reference.

3. MPRAGE correction options

PseudoCT can apply automatic preprocessing to improve segmentation and registration to the MNI atlas, including correction of nose/neck wrap-around aliasing and recentering of the brain within the field of view.

Recommended

Leave automatic aliasing correction and recentering enabled. The application determines whether a correction is actually required, so leaving these options ON is the preferred approach in most cases.

The preprocessing controls are currently being revised, so their exact appearance may change between releases.

4. Start processing

Once the input paths are correct, click OK. MATLAB must remain open for the duration of the run. Cancelling or closing the dialog starts no processing.

Batch processing

Multiple subjects can be selected in one run using the batch file picker: 

run_pseudo_CT('profile', 'local-current', 'subjects', 'batch')

Select the first MPRAGE DICOM for each subject (or the desired NIfTI input for each subject), then click Done. PseudoCT processes the selected subjects sequentially and discovers each subject's UMAP from the expected folder structure.

Study consistency still applies

For a long-running study, run the batch with the same numbered pseudoCT release used for the rest of the study rather than switching versions midway through processing.

During processing

Local execution takes approximately 30 minutes per subject on an average workstation. MLSC execution is expected to take approximately 1 hour per subject, excluding queue wait. The exact time depends on the workstation, cluster, and input data.

MATLAB prints stage-by-stage status messages and writes a detailed run log in MR_PET.

Interrupting a run

It is safe to interrupt pseudoCT, but interruption stops the current processing run. Intermediate files generated up to that point are retained.

Starting pseudoCT again for the same subject restarts processing from the beginning and overwrites existing processing files as needed.

Keep MATLAB running

Closing MATLAB or interrupting execution stops the local run. For MLSC, MATLAB must remain open while the cluster job is monitored and while local finalization is performed.

Outputs

PseudoCT creates the required output directories automatically. After a successful LOCAL - Current run, the subject directory contains: 

<subject>/
├── MR/
│   ├── MPRAGE/
│   ├── UMAP/
│   └── pseudo_muMAP/
│       └── final DICOM pseudoCT series
└── MR_PET/
    ├── att_map.nii
    ├── Fusion_MR_Pseudo_CT_validation.tiff
    ├── MPRAGE_spm.nii
    ├── MPRAGE_spm_normalized.nii
    ├── Pseudo_CT_AC_Version.txt
    ├── pseudo_CT_local-current_*.log
    └── pseudo_CT_profile_summary.txt

Standard remote profiles use the same final output layout after cluster processing and local finalization. Their required output is MR_PET/att_map.nii; the QC fusion TIFF, version record, and normalized MPRAGE are included when produced. MPRAGE-only profiles do not require a UMAP and produce NIfTI output only, so they do not create the final DICOM series under MR/pseudo_muMAP/.

MR/pseudo_muMAP/

The final pseudoCT is written here as a DICOM series for downstream PET/MR use.

att_map.nii

The final pseudoCT attenuation map in NIfTI format.

Fusion_MR_Pseudo_CT_validation.tiff

QC image used to inspect MPRAGE/pseudoCT coregistration.

pseudo_CT_local-current_*.log

Detailed processing log for the subject.

pseudo_CT_profile_summary.txt

Concise provenance record of the selected profile, important settings, and MATLAB environment.

Pseudo_CT_AC_Version.txt

Records the pseudoCT software version and associated release history.

Profile provenance

The profile summary is useful when checking or reporting exactly how a subject was processed.

During processing, intermediate files are staged under MR_PET/tmp/. On a successful run this temporary directory is cleaned up. If processing is interrupted, intermediate files are retained.

Quality control

Every generated pseudoCT should be visually inspected before it is used for PET attenuation correction. QC has two parts: coregistration review and direct inspection of the final attenuation map.

1. Check MPRAGE / pseudoCT coregistration

Open Fusion_MR_Pseudo_CT_validation.tiff from MR_PET. Inspect the overlaid MPRAGE and pseudoCT in all displayed orientations.

Look for:

  • consistent alignment of the pseudoCT with the MPRAGE anatomy;
  • agreement of the skull and brain contours;
  • reasonable alignment around the nose, sinuses, and posterior head;
  • no gross atlas-registration mismatch;
  • no missing, displaced, or obviously distorted skull regions;
  • no obvious failure related to poor positioning of the brain within the field of view.

2. Inspect the final DICOM pseudoCT

Open the DICOM series in MR/pseudo_muMAP/ using a proper DICOM image viewer and scroll through the entire volume. Do not rely only on the TIFF fusion image.

Inspect for unexpected attenuation values or artifacts inside and outside the head. A known failure mode is background noise in the MPRAGE being segmented and classified as soft tissue instead of air, producing spurious tissue-like attenuation in the background.

If background tissue-like artifacts are present

Do not use the pseudoCT without further review. Clean the MPRAGE background, save the cleaned image as a NIfTI file under MR_PET, and rerun pseudoCT. A dedicated background-cleanup tool is planned for release.

Troubleshooting

Problem What to check
run_pseudo_CT is not found Confirm that the actual pseudoCT_standalone-latest or numbered-release directory was added to the MATLAB path.
The UMAP field does not auto-populate Confirm that the subject contains an MR/UMAP folder with the correct UMAP acquisition and that the MPRAGE comes from the expected subject directory.
Processing was interrupted Intermediate files may remain under MR_PET. Rerun pseudoCT; processing restarts from the beginning and overwrites existing processing files as needed.
MPRAGE and pseudoCT are visibly misregistered Do not use the result. Verify the selected MPRAGE, inspect positioning, leave the automatic correction options enabled, and rerun. Review the log if the problem persists.
Soft-tissue-like attenuation appears in the background Inspect the MPRAGE for background noise. Clean the background, place the resulting NIfTI in MR_PET, and rerun pseudoCT.
Launchpad profile confusion Only launchpad-legacy is selectable (availability restoration only). The deprecated keys (launchpad, launchpad-mprage-only) are never shown in the selector and are not supported. Use LOCAL - Current for routine processing.
MLSC does not submit Confirm the login dialog was accepted with correct credentials. Cancelling the login dialog or the account-selection dialog stops before submission, and a user with zero available accounts cannot submit. Check the run log for the exact stage message. Retain the failure detail for support.
MLSC finishes without an attenuation map A finished cluster job alone is not sufficient. Confirm that MR_PET/att_map.nii is present and non-empty. Local finalization is not started when this check fails; retain the log and temporary files for diagnosis.
When asking for help

Keep the run log, pseudo_CT_profile_summary.txt, QC TIFF, and software version available. These files usually provide the most useful first-pass information for diagnosing a failed or suspicious run.
