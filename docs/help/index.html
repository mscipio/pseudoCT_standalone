Overview

PseudoCT generates a subject-specific attenuation map from a T1-weighted MPRAGE using the SPM8-based atlas method described by Izquierdo-Garcia et al. It is intended for PET/MR workflows at the Athinoula A. Martinos Center for Biomedical Imaging.

Before processing

Choose the profile that matches the input/reference and output policy, keep MATLAB open during a run, and review the QC before using the generated map.

D. Izquierdo-Garcia, A.E. Hansen, S. Förster, D. Benoit, S. Schachoff, S. Fürst, K.T. Chen, D.B. Chonde, and C. Catana. An SPM8-based Approach for Attenuation Correction Combining Segmentation and Non-rigid Template Formation: Application to Simultaneous PET/MR Brain Imaging. Journal of Nuclear Medicine. 2014;55(11):1825–1830.

When using the method, cite the publication and acknowledge the software as appropriate; see the repository's release history.

Quick start

  1. Load the deployed installation. 
    addpath('/usr/pubsw/packages/mrpet/standalone_apps/PseudoCT/pseudoCT_standalone-latest')
run_pseudo_CT
  2. Select one of the four supported profiles. The standard profiles use an MPRAGE and UMAP reference; MPRAGE-only profiles do not require UMAP.
  3. Select or confirm the input files. Use the GUI file selectors and verify that the subject and reference belong together.
  4. Wait for the run to finish. For MLSC, leave MATLAB open while the job is monitored and outputs are verified and finalized.
  5. Review the outputs and QC. Do not infer scientific completion from job submission or a scheduler state alone.

For a long-running study, use the same deployed numbered release throughout the study. See Installation for requirements.

Preparing input data

Standard profiles

MPRAGE + UMAP

Provide the MPRAGE and its matched UMAP reference. If the reference is omitted, the application may discover it from the subject layout. Confirm the selected files before submitting.

MPRAGE-only profiles

MPRAGE only

Provide an MPRAGE without a UMAP reference. These profiles use NIfTI-only output and reject UMAP input.

Supported MPRAGE inputs include DICOM series and NIfTI where available in the selected workflow. Keep source data unchanged and use the correct subject layout. For multi-subject CLI requests, pair MPRAGE and UMAP entries by position.

MLSC workflow

MLSC processing stages work on the cluster and returns results to the subject's shared workspace. The local MATLAB session submits and monitors the job and completes local output finalization.

  • Use the supported MLSC profile and an account authorized for the project.
  • Ensure the subject workspace and inputs are accessible from the cluster.
  • Keep MATLAB open until monitoring and output verification finish.
  • Do not treat accepted submission or Slurm COMPLETED alone as a verified pseudoCT result.

Authentication is handled by the supported application flow. Never place passwords, private keys, or other credential values in CLI arguments, environment variables, request files, or logs.

Outputs

Processing directory

Outputs are organized under the subject's MR_PET/ directory.

Attenuation map

The NIfTI attenuation map is named att_map.nii.

QC and version

A fusion QC image and software version record accompany the result.

DICOM

Standard profiles write DICOM output under MR/pseudo_muMAP/; MPRAGE-only profiles do not produce DICOM.

Temporary processing files are kept separate from final outputs. Preserve the generated QC and output records with the subject's processing results.

Quality control

Review QC for every subject before using an attenuation map in PET processing.

  • Inspect the MPRAGE/pseudoCT fusion for registration and anatomical coverage.
  • Scroll through the final volume and check for missing anatomy or unexpected attenuation outside the head.
  • Confirm that outputs belong to the intended subject and that workflow completion was verified.
  • Document any failure or questionable result; do not assume that one successful subject establishes general accuracy.

Troubleshooting

  • Input not found: check the MPRAGE path, subject directory, and file readability.
  • Reference missing: select the matched UMAP explicitly, or choose an MPRAGE-only profile if appropriate.
  • Dependency or artifact validation failed: stop and contact the application maintainer; do not substitute a different runtime or resource path.
  • MLSC still running: leave MATLAB open and allow the existing monitor to finish; do not submit a duplicate job.
  • QC or outputs incomplete: treat the run as unverified and retain its diagnostics for support.
